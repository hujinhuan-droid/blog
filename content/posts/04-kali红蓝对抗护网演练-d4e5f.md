# 红蓝对抗与护网演练：从攻击者视角看企业防御

> 红蓝对抗（Red Team / Blue Team）是检验企业安全防御能力的最有效方式之一。红队模拟真实攻击者，蓝队负责监测、防御与响应。护网行动（HW行动）就是国家级别的红蓝对抗演练。本文带你理解红蓝双方的攻防思路与实战手法。

## 一、红蓝对抗概述

| 角色 | 目标 | 手段 |
|------|------|------|
| 红队 | 突破企业防御，找到漏洞 | 模拟攻击者全链攻击 |
| 蓝队 | 发现攻击、及时防御、加固 | 日志监控、威胁狩猎、应急响应 |
| 紫队 | 红蓝协同 | 攻防复盘、能力提升 |

### 护网行动（HW）

- 由国家主管部门组织，每年一次的攻防演练
- 红队（攻击方）通过授权对目标企业进行实战攻击
- 蓝队负责防守，防止被拿下
- 目标是发现并修复高危漏洞，提升整体安全水位

## 二、红队攻击流程（全景）

```
1. 侦察（OSINT/资产收集）
   ↓
2. 武器化（免杀载荷、钓鱼）
   ↓
3. 交付（邮件/链接/钓鱼）
   ↓
4. 利用（漏洞利用、远程执行）
   ↓
5. 安装（后门、持久化）
   ↓
6. 指挥控制（C2）
   ↓
7. 达成目标（数据/权限/破坏）
```

### 红队常用武器库（Kali 视角）

- **信息收集**：Nmap、Maltego、Shodan、Fofa
- **漏洞扫描**：Nessus、OpenVAS、AWVS
- **漏洞利用**：Metasploit、Burp Suite、sqlmap
- **免杀与木马**：msfvenom、Cobalt Strike、Veil
- **内网渗透**：fscan、mimikatz、proxychains、chisel
- **C2 框架**：Cobalt Strike、Metasploit、Sliver

## 三、蓝队防守思路

蓝队要在攻击发生前、中、后快速响应。

### 防御框架（NIST 5 阶段）

| 阶段 | 蓝队动作 |
|------|----------|
| 识别 | 资产盘点、基线、漏洞管理 |
| 保护 | 补丁、加固、零信任、最小权限 |
| 检测 | EDR/SIEM/NDR、日志监控、威胁狩猎 |
| 响应 | 应急响应、隔离、取证、恢复 |
| 恢复 | 备份恢复、复盘、持续改进 |

### 蓝队关键检测点

- 异常外联（C2 通信）
- 异常进程/服务启动
- 横向移动特征（SMB、计划任务）
- 钓鱼邮件告警
- 权限提升行为

## 四、红蓝对抗实战场景

### 场景1：钓鱼 + 横向移动

```
红队：
1. 发送钓鱼邮件（伪装 IT）
2. 员工点击 → 恶意载荷落地
3. 拿下工作站 → 尝试 SMB 横向移动 → 域控

蓝队：
1. 邮件网关检测外部仿冒
2. EDR 发现可疑进程/行为
3. 阻断 SMB 流量，隔离主机
4. 溯源钓鱼邮件来源并处置
```

### 场景2：VPN 爆破

```
红队：对 VPN 入口进行凭据喷洒（弱密码）
蓝队：账号锁定策略、异常登录告警、MFA 强制
```

### 场景3：供应链 / 0day

```
红队：利用已公开的 0day 漏洞（CVE）
蓝队：情报共享、补丁优先级、应急流程
```

## 五、攻防复盘：红蓝交叉验证

演练结束后的**复盘**是提升的关键：

```
攻击路径复盘
- 红队：还原攻击链、用了哪些技术
- 蓝队：哪里检测到/没检测到、响应时间

发现闭环
- 漏洞是否修复
- 检测规则是否更新
- 流程是否优化

指标度量
- 攻击成功率 / 检测覆盖率 / 响应时间 MTTR
```

## 六、红蓝双方技能地图

| 红队必备 | 蓝队必备 |
|---------|---------|
| 渗透测试方法论 | 安全运营（SOC） |
| Web/内网/免杀/钓鱼 | 日志分析、溯源 |
| 漏洞利用 | 威胁情报 |
| 代码审计 | 应急响应 |
| 社会工程学 | 安全合规 |

## 安全合规

> 红蓝对抗只能在**授权**的环境（企业自身、靶场、护网演练）中进行。护网由主管部门统一组织，企业必须遵守规则。任何未授权的"红队"行为都是违法的。

## 小结

- 红蓝对抗 = 攻击者思维 vs 防御者体系
- 红队关注"能不能打穿"，蓝队关注"能不能发现并挡住"
- 护网是国家级演练，倒逼企业安全建设
- 攻防复盘（紫队）是提升双方能力的核心
- 安全不是一劳永逸，持续对抗才有进步
