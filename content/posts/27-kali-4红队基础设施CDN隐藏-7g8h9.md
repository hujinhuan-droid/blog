# 红队基础设施：API 前置与 CDN 隐藏

> 红队攻击不仅要有技术，还要有**隐蔽的"房子"**。本文介绍红队基础设施的搭建思路：域名、VPS、CDN 前置、域名前置，让 C2 流量看起来像正常业务。

## 一、红队基础设施全景

```
[攻击者]
   │
   ▼
[重定向器 Redirector] —— 反制/隐藏
   │
[CDN / WAF / 云函数] —— 混淆流量
   │
[真实 C2 服务器]（海外 VPS）
   │
[受害主机 Beacon]
```

## 二、域名与基础设施

### 域名选择

- 高信誉域名（.com/.net，历史悠）
- 域名前置：CDN 背后的域名
- 伪装子域名：cdn-c2.xxx.com

### VPS 要求

- 海外：多地域、多供应商
- 长期稳定（云厂商的合规性好）
- 非高危封端口

## 三、CDN 隐藏真实 IP

### 原理

CDN 将流量转发到源站，源站 IP 不暴露。红队把 C2 部署在 CDN 后面，蓝队看到的是 CDN 的 IP。

### 配置

```bash
1. 购买域名
2. 配置 Cloudflare（免费版）
3. 回源地址填 VPS IP
4. C2 Listener 监听 443（HTTPS）
5. 受害机连接域名 → 走 CDN → 到源站
```

### 风险与绕过

| 风险 | 说明 |
|------|------|
| 证书指纹 | 蓝队可识别 CDN 证书 |
| 无证书 | 伪装不了 |
| 反查 | CDN 可暴露源站 |

## 四、域名前置（Domain Fronting）

> 通过 CDN 的 HTTP Host 头混淆，让流量看起来访问的是高信誉域名，实际去往 C2。

```
请求：https://s3.amazonaws.com/xxx（高信誉域名）
Host 头：s3.amazonaws.com（表面）
SNI：s3.amazonaws.com（表面）
实际路由：通过 CDN 转发到 c2.example.com（内部）
```

> 现状：主流 CDN 已限制，仅部分仍可用。

## 五、其他基础设施技术

| 技术 | 说明 |
|------|------|
| Redirector | 中间跳板（nginx/apache 转发） |
| Multi-Hop | 多层代理链 |
| DNS 隧道 | DNS 协议传数据 |
| TOR 出口 | 匿名出口 |
| 匿名 VPS | 不实名 |

## 六、基础设施运维

```
- 证书管理（Let's Encrypt 自动续）
- 心跳保活
- 多节点冗余
- 日志清理（合规内）
- 突然失效处理（自动切换）
```

## 七、防御者视角

蓝队识别红队基础设施：

```
- 新域名 / 短命域名（未注册历史）
- 异常证书 / 自签
- CDN 背后的源站暴露
- 高频心跳（Beacon 特征）
- 异常 User-Agent
```

## 安全合规

> 红队基础设施相关技术，只能在**授权红队演练**中使用。搭建隐藏 C2 攻击他人 = 违法犯罪。

## 小结

- 基础设施 = 域名 + VPS + CDN/前置
- CDN 前置隐藏源站是核心思路
- 域名前置/重定向提升隐蔽性
- 蓝队靠"域名信誉 + 流量特征"反制
- 合规：只在授权演练中用
