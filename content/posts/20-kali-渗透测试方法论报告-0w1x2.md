# 渗透测试方法论：从 PTES 标准到专业报告撰写

> 前面 19 篇都是"术"，这篇讲"法"——**渗透测试的标准流程与专业报告**。一个合格的渗透测试不只是"打下来"，而是有章法、有边界、有交付物的系统性工程。掌握方法论，让你的测试从"黑客炫技"变成"专业服务"。

## 一、渗透测试标准框架

| 标准 | 全称 | 侧重 |
|------|------|------|
| PTES | Penetration Testing Execution Standard | 流程最细 |
| OWASP | Web 应用标准 | Web 专项 |
| OSSTMM | 开源安全测试方法论 | 全面审计 |
| NIST SP 800-115 | 美国 NIST 标准 | 官方合规 |
| PTPS | 渗透测试 | 中国 GB/T 引导 |

### PTES 七个阶段

```
1. 前期交互（Pre-engagement）—— 范围/授权
2. 情报收集（Intelligence Gathering）—— OSINT/扫描
3. 威胁建模（Threat Modeling）—— 目标/资产
4. 漏洞分析（Vulnerability Analysis）—— 发现
5. 漏洞利用（Exploitation）—— 验证
6. 后渗透（Post-Exploitation）—— 维持/提权
7. 报告（Reporting）—— 交付

（外加：清理痕迹/恢复环境）
```

## 二、前期交互（必须的）

### 授权书（Scope/Authorization）

```
授权范围：IP/域名/系统
测试类型：黑盒/白盒/灰盒
允许的操作：能否提权、能否删除
时间窗口：起始-结束
联系人：紧急情况通知
紧急预案：异常处理
```

> 没有授权书 = 违法。**这是底线。**

## 三、测试过程记录

### 每个阶段产出记录

```
侦察：目标清单、网络拓扑、服务版本
扫描：发现的端口、服务、CVE
利用：使用的模块、命令、时间
后渗透：权限、横向路径
证据：截图、报文、命令输出
```

> 建议全程截图，并用时间戳记录，作为报告佐证。

## 四、漏洞评级（CVSS）

| 等级 | 分数 | 示例 |
|------|------|------|
| Critical | 9.0-10.0 | 远程 RCE |
| High | 7.0-8.9 | 未授权访问 |
| Medium | 4.0-6.9 | 信息泄露 |
| Low | 0.1-3.9 | 配置警告 |

## 五、渗透测试报告结构（模板）

```
封面（客户/测试方/日期/密级）
执行摘要（Executive Summary）
  - 总体结论
  - 关键漏洞（3-5 个）
  - 风险统计表

测试范围与方法
  - 授权书
  - 测试日期
  - 方法（PTES/OWASP）

漏洞明细
  - 每个漏洞：
    等级、影响范围
    截图/证据
    复现步骤
    修复建议

修复建议汇总
附录
  - 工具列表
  - 数据汇总表
```

### 报告原则

- **面向管理层**：结论先行，讲业务风险
- **面向技术人员**：复现步骤、修复代码
- 数据真实可复核
- 符合客户模板（如安全合规要求）

## 六、Kali 辅助报告工具

| 工具 | 用途 |
|------|------|
| Metasploit | 报告生成（XML） |
| Farad/report | 报告模板 |
| pandoc | md → 报告转换 |
| 文本编辑器 | 手动撰写 |

## 七、职业操守

- 绝不超出授权范围
- 敏感数据（如数据库内容）绝不外泄
- 报告交付后清理痕迹
- 客户数据保密

## 安全合规

> 渗透测试本身是专业服务，但所有动作都必须在授权、合规框架内。未授权的渗透=非法入侵。

## 小结

- 方法论比技术更重要：PTES 七阶段是框架
- 授权书是第一道门槛
- 全程记录 = 报告的证据
- 报告是交付物的核心，要面向读者分层
- 专业 = 有规范、有记录、有边界
