# 游戏 AI 代理入门：从视觉到行动的完整架构

> 你有没有想过：让代码替你在游戏里自动打怪、捡装备、卖战利品？这就是**游戏 AI 代理（Game Agent）**。本文从零开始，讲清一个能"看见游戏、做出决策、操作游戏"的 AI 代理是怎么组成的。全程基于**开源游戏与自建沙盒**，完全合法。

## 一、游戏 AI 代理是什么

一个游戏 AI 代理 = 一套"眼、脑、手"系统：

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   眼睛       │     │   大脑       │     │   手        │
│  视觉感知    │ →  │  决策逻辑    │ →  │  操作执行   │
│  OpenCV 截图 │     │  状态机/AI   │     │  键鼠模拟   │
└─────────────┘     └─────────────┘     └─────────────┘
```

| 模块 | 职责 | 常用库 |
|------|------|--------|
| 感知 | 获取画面、识别目标 | mss / OpenCV / Pillow |
| 决策 | 判断"下一步做什么" | 状态机 / 行为树 / 强化学习 |
| 操作 | 模拟鼠标键盘 | pyautogui / pydirectinput |

## 二、一个最简单的代理（读屏 + 点击）

```python
import time
import pyautogui
import mss
import cv2
import numpy as np

# 1. 截屏
with mss.mss() as sct:
    screen = np.array(sct.grab(sct.monitors[1]))
    img = cv2.cvtColor(screen, cv2.COLOR_BGRA2BGR)

# 2. 查找目标（颜色匹配，找"金色物品"）
lower = np.array([30, 200, 200])   # BGR 金色
upper = np.array([60, 255, 255])
mask = cv2.inRange(img, lower, upper)
points = cv2.findNonZero(mask)

# 3. 有目标就点击
if points is not None:
    x, y = points.mean(axis=0)[0]   # 取中心
    pyautogui.click(x, y)
```

> 这已经是一个最简代理的骨架：**截图 → 识别 → 点击**。

## 三、代理的分层设计

一个可维护的代理一定要分层：

```
game_agent/
├── vision.py      # 视觉层：截图、识别、定位
├── brain.py       # 决策层：状态机/行为树/RL
├── hands.py       # 操作层：鼠标键盘封装
├── agent.py       # 主循环：把三层串起来
└── config.py      # 参数配置
```

### 主循环（agent.py 核心）

```python
while running:
    state = vision.observe()      # 看：获取当前状态
    action = brain.decide(state)  # 想：决定做什么
    hands.execute(action)         # 做：执行动作
    time.sleep(0.1)               # 控制节奏
```

## 四、状态机：最简单的"大脑"

自动打怪-拾取-售卖可以用**状态机**描述：

```
[寻怪] → 发现敌人 → [战斗]
  ↑                     ↓
  │                 战斗结束
  │                     ↓
[空闲] ← [拾取] ← 发现掉落
  ↓
发现物品过多
  ↓
[回城售卖] → 卖完 → [空闲]
```

```python
class State:
    IDLE = "idle"
    FIGHT = "fight"
    LOOT = "loot"
    SELL = "sell"

class Brain:
    def __init__(self):
        self.state = State.IDLE

    def decide(self, obs):
        if self.state == State.IDLE:
            if obs["enemy_nearby"]:
                self.state = State.FIGHT
            elif obs["drop_nearby"]:
                self.state = State.LOOT
            elif obs["inventory_full"]:
                self.state = State.SELL
        elif self.state == State.FIGHT:
            if not obs["enemy_nearby"]:
                self.state = State.LOOT if obs["drop_nearby"] else State.IDLE
        ...
        return self.state
```

## 五、感知层：游戏状态怎么获取

获取游戏状态有三种主流方式（按合法性从高到低）：

| 方式 | 原理 | 适用 |
|------|------|------|
| 图像识别 | 截屏 + OpenCV 找目标 | 任何游戏（不读内存） |
| 窗口信息 | 读窗口标题/位置 | 定位游戏窗口 |
| 内存读取 | 读进程内存 | 不推荐，易封号且违规 |

> 本系列全部采用**屏幕图像识别**，不碰内存，合法且通用。

## 六、安全与合规红线

- 只对**开源游戏、单机游戏、自建沙盒**做自动化
- 不碰联机竞技/MMO（违反 ToS，可能封号且违法）
- 不读进程内存、不注入、不修改游戏文件
- 本文项目均为"AI 玩开源游戏"学习项目

## 小结

- 游戏代理 = 感知 + 决策 + 操作 三层
- 最简代理：截图 → OpenCV 找目标 → pyautogui 点击
- 状态机是最实用的"大脑"（打怪/拾取/售卖）
- 屏幕识别是合法又通用的感知方式
- 只在开源/自建游戏里玩，红线不可越
